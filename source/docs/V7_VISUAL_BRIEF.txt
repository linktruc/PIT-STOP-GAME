4. ACTION-TO-ANIMATION MAPPING (VERY IMPORTANT)
====================================================================
This is critical.

Every gameplay task must correspond to a clear visible animation in the 3D scene.
Do NOT only change backend state or flash a button. The scene must visually respond.

EXAMPLES OF REQUIRED MAPPINGS
- Front jack task: when the front jack task becomes available and is completed by the assigned player, the visible front jack crew member must perform a lifting motion and the car front must visibly rise.
- Rear jack task: rear jack crew member performs the motion and car rear visibly rises.
- Wheel gun task: the specific gunner at that wheel should animate into action, using the wheel gun on the correct wheel.
- Wheel-off task: the specific crew member should remove the old tire from the correct corner.
- Wheel-on task: the assigned crew member should carry/position the new tire and mount it.
- Signal/release task: the supervising crew member should perform a visible release/confirmation gesture and the car should leave or visibly prepare to go.

GENERAL RULES
- The animation timing must correspond tightly with the actual gameplay event.
- If the player presses their action button successfully, the scene should immediately react.
- If a task is not yet available, the corresponding character should look idle or waiting.
- If a task is ready, the corresponding character can subtly indicate readiness.
- If a task is complete, that part of the crew should visibly move to the completed state.

PARALLEL TASKS
- When multiple tasks happen in parallel, the scene must show that parallelism.
- Example: multiple tire crew members should animate concurrently when those tasks unlock concurrently.
- This is essential for communicating teamwork.

BOTS
- Bots should also animate meaningfully.
- Bot-driven tasks must still be visible in the scene and follow the game logic.
- Bots must not feel fake or absent.
