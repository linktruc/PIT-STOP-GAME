## Rolling frontier policy

The recent slot uses the latest authoritative event time with task-ID tie break; completedAt is the fallback for snapshots without events. CURRENT selects the oldest enabled AVAILABLE task, with stable task-ID tie break. New descendants have later eligibility, so unrelated simultaneous progress cannot preempt an existing frontier. NEXT is a direct unfinished successor whose other prerequisites are already complete; otherwise WAIT/PARALLEL. Recent→Active is a temporal viewport, not an invented dependency edge. The full graph shows actual parallelism. Derived data is memoized on room snapshots; the mini strip receives a stable open callback and no interpolating frame clock.

## Scene sharing and animation policy

Both paths invoke `createPitGarageScene`. That factory owns the same detailed car geometry, garage props, lighting/materials, 22 rigs, wheels, guns, jacks, two-bone hand targets, task receipts, old/new wheel travel, lowering, withdrawal and departure gate. Renderer/camera options are separate from geometry. A newly accepted HUMAN task catches up queued prerequisites consistently in both player and spectator paths; official data/timestamps are never mutated. First/mid-round snapshots settle current poses rather than replaying history. After an observation gap over 8 seconds with at least six missed completions, the same-round view also settles its current pose instead of queueing an old stop; an isolated fresh lift after a long wait still animates. A regression test verifies this without changing authoritative state.

The preview pool updates room data independently, renders visible cards in a rotating budget (up to two per 250ms tick; one when measured submission/copy cost exceeds 45ms), and caps cached worlds at eight. Card frequency drops as visible room count grows. Offscreen/background work is skipped. Only actual WebGL failure uses a clearly labeled live 2D fallback. The paired release QA fixture temporarily retains active status to inspect the shared departure renderer; it does not claim the production server sends that intermediate state. A completed active card removes its preview immediately, as required; departure remains implemented in the shared world and shown in the focused/player scene.
